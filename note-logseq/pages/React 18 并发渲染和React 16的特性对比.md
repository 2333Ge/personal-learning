- # React 18 并发渲染（核心突出版）
  并发渲染，本质就是：
  **让 React 可以同时“准备多个版本的 UI”，并且可以随时中断、抛弃、切换，不再必须一条道走到黑。**
  
  它和 React 16 那种“只是切小片不卡页面”完全不是一个级别。
- ## 1. 真正的可中断、可抛弃、可恢复
  React 16：
- 可以暂停让出主线程
- 但**一旦开始更新，就必须做完**，不能放弃
  
  React 18 并发：
- 可以**完全中断**一个低优先级更新
- 甚至直接**扔掉**这次渲染结果
- 等优先级更高的操作做完，再重新开始
- 中间状态不会暴露给用户
  
  这才是**真正并发**。
- ## 2. 优先级调度（插队机制）
- 用户输入、点击 = 高优先级
- 列表渲染、大数据统计 = 低优先级
  
  当你在输入框打字时：
- React 会**立即暂停**正在渲染的长列表
- 先把输入内容更新出来
- 再回头继续渲染列表
  用户完全感觉不到卡顿。
- ## 3. 同一组件可存在“多个状态版本”
  这是 18 最核心、16 完全没有的特性：
  
  组件可以同时存在：
- 一个“当前显示的稳定版本”
- 一个“后台正在计算的新版本”
  
  新版本没算完之前，**老版本继续显示**，不会出现半拉子 UI、不会闪烁、不会卡顿。
- ## 4. 非阻塞更新（不锁主线程）
  以前大更新会：
- 计算 → 阻塞 → 渲染
  现在并发模式：
- 后台计算
- 不阻塞交互
- 算完再一次性替换 UI
- ## 5. 配合新 Hooks 手动控制优先级
- `useTransition`：把更新标记为**非紧急、可中断**
- `useDeferredValue`：延迟某个值的更新，不阻塞界面
  
  这两个是 18 并发能力的**直接使用入口**，16 根本没有。

- # 最终口述总结（面试满分版）
  React 18 的并发渲染，是基于 Fiber 架构真正开启的**异步非阻塞更新机制**。
  它不再是简单的时间分片，而是支持**可中断、可抛弃、可插队**的优先级调度。
  能在后台准备多个 UI 版本，不阻塞用户交互，配合 useTransition、useDeferredValue 让开发者手动控制更新优先级，从根本上解决大型应用的卡顿问题。
