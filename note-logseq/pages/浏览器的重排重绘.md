- 浏览器拿到 HTML、CSS 后，会经历这几步：
	- **构建 DOM 树** → 解析 HTML
	- **构建 CSSOM 树** → 解析 CSS
	- **生成 渲染树（Render Tree）** → 只包含可见节点
	- **布局（Layout）** → 计算元素位置、大小 → **对应重排**
	- **绘制（Paint）** → 填充像素、颜色、背景 → **对应重绘**
	- **合成（Composite）** → 图层合并展示
- 浏览器渲染页面核心流程：**构建 DOM → 构建 CSSOM → 生成渲染树 → 布局 (重排) → 绘制 (重绘) → 合成**
- ### 1. 重排（回流 / Reflow）
- **定义**：元素**几何属性**（位置、宽高、边距、字体大小等）发生变化，浏览器重新计算所有受影响元素的布局位置。
- 触发条件：改变布局相关样式、DOM 结构、窗口大小、字体等。
- **开销大**：会递归计算父 / 子节点布局，是性能主要损耗点。
- ### 2. 重绘（Repaint）
- **定义**：元素**外观样式**（颜色、背景、阴影、透明度等）改变，但布局不变，浏览器仅重新绘制像素。
- 触发条件：修改颜色、background、box-shadow、outline 等。
- 开销比重排小，但频繁触发仍影响性能。
- ### 3. 合成（Composite）
- 将图层合并到屏幕，**开销最小**。
- 仅修改 `transform`、`opacity` 时，直接走合成层，不触发重排、重绘，性能最优。
- ## 如何减少重排重绘（性能优化）
- ### 1. 批量修改 DOM
- 使用 `class` 一次性修改样式，不要逐条改
- 使用 **DocumentFragment** 离线操作 DOM
- ### 2. 避免频繁读取布局属性
  
  不要在循环里读取 `offsetTop / clientWidth / getBoundingClientRect`。
- ### 3. 使用 CSS3 硬件加速（最优方案）
  
  `transform` 和 `opacity` 不会触发重排重绘，只触发**合成层**。
- ### 4. 脱离文档流
  
  绝对定位、固定定位让元素独立图层，减少重排范围。
- ### 5. 防抖节流（resize /scroll）
  
  避免高频触发布局计算。
